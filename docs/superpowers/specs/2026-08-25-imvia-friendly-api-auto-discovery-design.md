# IMVIA Studio 友好型外部 API 自动识别设计

## 状态与优先级

本设计已在对话中确认，定义 IMVIA Studio 新建外部 API 连接时的自动识别、模型目录和工作台交互。

本设计是 `2026-08-24-imvia-multi-provider-api-connectors-design.md` 的增量替代规格。发生冲突时，以本文为准，具体包括：

- 新建连接不再让用户选择通用 REST 类型、填写能力、模型或接口映射。
- 新建连接不再向用户展示接口映射 JSON 或高级设置 JSON。
- 接口路径、请求格式、异步轮询和结果解析改由受信任的内部适配器维护。
- 已有旧版自定义 REST 连接继续保留和运行，不迁移、不覆盖其原始映射。

## 背景

当前外部 API 表单要求用户填写服务商类型、图片或视频能力、接口映射 JSON 和高级设置 JSON。这个交互把连接器内部实现暴露给了普通用户；用户还必须提前知道模型、请求路径、返回字段和异步任务协议。

当前提供商描述符中的外部模型也是静态的。默认 `custom-rest` 只有 `Auto`，连接存储又限制模型必须来自静态描述符，所以工作台不能根据用户填写的 API 自动读取该 API 的实际模型。

目标交互应该让用户只提供完成鉴权所必需的信息，模型和协议由 IMVIA 自动识别。

## 产品决策

采用“自动识别协议 + 受信任服务商适配器”的混合方案：

- 用户只填写 API 名称、API 地址和 API Key。
- API 名称可选但鼓励填写；留空时使用规范化地址的域名。
- 模型名称直接采用 API 返回的 `name` 或 `id`，IMVIA 不擅自改名。
- OpenAI-compatible API 使用标准只读模型发现规则。
- 图片和视频生成通过明确的适配器执行，不根据模型名称盲猜接口。
- API 返回的模型全部保留并可查看；是否能够在工作台中执行由适配器能力决定。
- 外部 API 任务失败时直接返回外部服务错误，绝不调用或回退到 Lovart。

不采用任意 REST API 猜测方案。单凭地址和密钥无法可靠推断提交路径、字段映射、异步状态、结果结构和视频接口。

## 目标

1. 让用户不接触 JSON 即可连接受支持的外部图片或视频生成 API。
2. 自动读取并展示 API 返回的原始模型名称和 ID。
3. 清楚地区分“API 返回了模型”和“当前适配器可以执行该模型”。
4. 为 OpenAI-compatible 图片生成和后续服务商视频适配器建立稳定扩展边界。
5. 保持凭据隔离、任务快照不可变和外部提供商不回退 Lovart 等现有安全约束。
6. 保留已有旧版自定义 REST 连接，不造成配置或凭据丢失。

## 非目标

- 不承诺识别任意自定义 REST API。
- 不根据模型名称中的 `image`、`video` 等文字直接猜测调用协议。
- 不让网页直接调用外部 API。
- 不在自动探测期间创建图片、视频、项目或计费任务。
- 不把文本、语音、嵌入或其他非图片/视频模型当作可生成模型。
- 不增加跨提供商自动故障转移。
- 不修改独立 Lovart 插件、其仓库、凭据或执行流程。

## 用户体验

### 添加连接

“设置 → API 连接 → 添加 API”使用单页简化表单，只包含：

1. **API 名称**：可选，放在第一项，说明“建议填写，方便区分多个 API”。
2. **API 地址**：必填，示例为 `https://api.example.com/v1`。
3. **API Key**：必填，通过 IMVIA 本机安全窗口输入，不在网页表单中输入。
4. **连接并识别**：唯一主要操作。

原有下列控件从新建和新版编辑流程中移除：

- 服务商类型选择器
- 图片、视频能力复选框
- 接口映射 JSON
- 高级设置 JSON
- 用户维护的模型列表

地址输入允许缺少协议但形似合法域名的值；这种情况下前端明确补全为 `https://` 并在提交前展示规范化结果。地址必须最终解析为无用户名、密码、查询参数或片段的 HTTPS URL。尾部斜杠被统一规范化。

API 名称为空时，连接服务使用规范化 URL 的主机名作为名称。如果名称与现有连接重复，则添加稳定的数字后缀，例如 `api.example.com 2`，而不是让连接失败。

### 识别进度

点击“连接并识别”后，界面按实际阶段显示：

```text
正在验证地址
→ 正在打开安全密钥窗口
→ 正在验证密钥
→ 正在识别接口
→ 正在读取模型
→ 已找到 N 个模型
→ 连接完成
```

关闭安全窗口或未提供密钥时，流程回到可重试状态，不创建启用连接。

连接识别失败时保留一个不含密钥的“未启用草稿”。用户可以修改地址、更新密钥或删除草稿。未启用草稿不参与自动路由，也不出现在生成模型选择器中。

### 连接卡片

启用连接的卡片显示：

- API 名称和域名
- 识别出的协议或服务商名称
- 已连接、需要重新验证、连接失败或未发现模型等状态
- 已发现模型总数，以及可执行的图片和视频模型数量
- 最近成功同步模型的时间
- 刷新模型、编辑名称、修改地址、更新密钥、停用和删除操作

“编辑名称”只修改显示名称，不改变连接身份或任务路由。修改地址或密钥必须重新识别并生成新的连接配置版本。

## 模型目录与展示

### 原始名称

模型目录保留 API 返回的原始身份：

- 同时有 `name` 和 `id`：主要显示 `name`，次要显示 `id`。
- 只有 `id`：直接显示 `id`。
- 只有 `name`：在适配器能够提供稳定标识时才接受；否则模型响应被视为不可用结构。
- 搜索同时匹配名称和 ID。

IMVIA 不翻译、缩写或重新命名外部模型。适配器可以补充品牌、能力和兼容性元数据，但不能替换原始模型 ID。

### 可见性与可执行性

“连接详情”始终列出 API 返回且通过安全结构校验的全部模型。工作台生成选择器根据当前图片或视频模式分组：

1. **适用于当前任务**：适配器明确支持当前模式和模型。
2. **兼容性未确认**：适配器存在当前模式的通用执行路径，但无法确认该模型能力；允许用户选择并显示一次轻量提示。
3. **当前版本暂不支持调用**：API 返回了该模型，但没有当前模式的可靠执行路径；只在“查看全部 API 模型”中显示且禁用。

模型不会因为无法分类而从连接详情中消失。模型也不会仅因名称看起来像图片或视频而被错误启用。

### 模型目录记录

每条规范化模型记录至少包含：

```json
{
  "id": "provider-model-id",
  "display_name": "Provider model name",
  "capabilities": ["image"],
  "compatibility": "confirmed",
  "source": "api",
  "raw_index": 0
}
```

`capabilities` 只允许 `image` 和 `video`。`compatibility` 只允许：

- `confirmed`：适配器明确确认能力和执行路径。
- `unconfirmed`：存在当前模式通用执行路径，但模型能力未知。
- `unsupported`：没有可靠执行路径。

公共响应不返回完整原始模型对象，避免服务商响应中的意外敏感字段或超大元数据进入浏览器。`raw_index` 仅用于稳定保留上游顺序；不作为身份。

### 刷新规则

模型目录在以下时机刷新：

- 首次连接成功时强制刷新。
- 用户点击“刷新模型”时强制刷新。
- 上次成功同步超过 24 小时且用户重新打开工作台时静默刷新。
- 地址、密钥或适配器变化时强制重新识别。

刷新使用整体替换和新目录版本，不能部分覆盖。刷新失败时保留上次成功目录，并显示“模型列表可能已过期”；不得清空当前选择。单纯刷新模型目录不递增连接配置版本，也不使已经创建的任务失效。已经创建的任务继续使用任务快照中固定的模型记录和目录审计信息。

## 架构

```text
工作台简化表单
  → 连接草稿服务
  → 本机安全凭据窗口
  → 协议识别器
      → 受信任适配器匹配
      → OpenAI-compatible 只读探测
  → 模型目录服务
  → 连接配置与目录版本
  → 工作台提供商 / 模型选择
  → 不可变任务快照
  → 提供商执行路由器
  → 选定外部适配器
```

浏览器只访问本地 IMVIA HTTP 服务。协议探测、凭据解析、模型读取和外部生成都在服务端执行。

### 协议识别器

协议识别器接受规范化地址、凭据引用和受信任适配器注册表，返回一个识别结果：

```json
{
  "protocol": "openai-compatible",
  "adapter_id": "openai-images",
  "adapter_version": "1",
  "provider_label": "OpenAI-compatible",
  "models_endpoint": "https://api.example.com/v1/models"
}
```

识别顺序：

1. 使用静态受信任适配器规则匹配明确的服务商主机和响应特征。
2. 对输入路径执行 OpenAI-compatible 模型端点探测。
3. 输入路径以 `/v1` 结尾时先尝试同路径下的 `/models`；否则依次尝试同主机下的 `/v1/models` 和 `/models`。
4. 只接受受支持的成功响应结构；HTML、重定向登录页或未知 JSON 不算识别成功。

探测候选必须保持同一规范化主机、HTTPS 和允许的端口。重定向需要重新执行网络安全校验；默认不允许跨主机重定向。识别器不执行生成请求。

### 模型目录服务

模型目录服务负责：

- 调用识别结果指定的模型端点。
- 解析 OpenAI-compatible `data` 数组和适配器声明的受信任响应结构。
- 校验模型数量、字符串长度、唯一 ID 和响应体大小。
- 去重并稳定保留上游顺序。
- 使用适配器能力元数据标记模型兼容性。
- 创建不可变的目录版本和摘要。

协议识别器不直接保存连接，模型目录服务也不负责生成。二者通过明确的识别结果和规范化目录契约通信，可以独立测试和替换。

### 适配器注册表

每个适配器声明：

- `adapter_id` 和版本
- 可识别的协议、主机或响应特征
- 模型目录解析器
- 图片和视频能力判断规则
- 支持的提交、轮询、取消和结果导入操作
- 是否存在某个模式的通用执行路径

首版必须内置 OpenAI-compatible 模型发现和标准图片生成适配器。视频只有在匹配到受支持的视频适配器时才启用；不存在统一视频协议时不能用猜测填补。

新增服务商通过发布受信任适配器实现，用户界面和连接数据契约保持不变。网页配置不能创建或注入适配器代码。

### 连接存储

外部连接从静态提供商模型改为连接级动态目录。连接记录至少增加：

```json
{
  "connection_id": "stable-public-id",
  "name": "Mix API",
  "name_source": "user",
  "provider_id": "external-api",
  "base_url": "https://api.example.com/v1",
  "credential_ref": "opaque-local-reference",
  "status": "connected",
  "enabled": true,
  "protocol": "openai-compatible",
  "adapter_id": "openai-images",
  "adapter_version": "1",
  "config_revision": 2,
  "model_catalog_revision": 4,
  "model_catalog_digest": "sha256",
  "last_discovered_at": "2026-08-25T00:00:00.000Z",
  "last_discovery": {
    "status": "connected",
    "code": "CONNECTED"
  }
}
```

模型目录可以与连接文件一同保存或存入独立版本化文件，但必须通过连接 ID 和目录版本关联。公共连接响应只返回安全字段、规范化模型目录和脱敏状态。

现有静态提供商描述符不再是外部连接模型的权威来源。Lovart 继续使用自己的模型机制；外部任务使用选定连接的模型目录和适配器能力。

### API 与操作边界

现有连接 API 保留资源身份，但新建流程变为事务式操作：

1. 创建或更新未启用草稿，只保存非敏感名称和地址。
2. 通过现有本机凭据服务写入 API Key。
3. 调用连接的 `discover` 操作完成鉴权、协议识别和模型读取。
4. 成功后原子写入识别结果、模型目录并启用连接。
5. 失败时写入脱敏失败状态，连接保持未启用。

需要提供等价的服务端操作：

- 列出安全连接和连接级模型目录。
- 创建未启用连接草稿。
- 更新名称或地址。
- 通过安全窗口写入或替换凭据。
- 识别或重新识别连接。
- 刷新模型目录。
- 停用或删除连接。

识别和刷新不能接受用户提供的接口映射、响应路径表达式或任意请求模板。

## 任务快照与执行路由

外部任务快照固定保存：

```json
{
  "provider_id": "external-api",
  "connection_id": "stable-public-id",
  "connection_config_revision": 2,
  "model_catalog_revision": 4,
  "model_catalog_digest": "sha256",
  "adapter_id": "openai-images",
  "adapter_version": "1",
  "model": "provider-model-id",
  "selected_model": {
    "id": "provider-model-id",
    "display_name": "Provider model name",
    "capabilities": ["image"],
    "compatibility": "confirmed"
  },
  "selected_model_digest": "sha256",
  "mode": "image"
}
```

执行前必须验证：

- 连接存在、启用且属于外部提供商。
- 连接配置版本和适配器版本与任务快照一致；地址、密钥或适配器变化后，旧任务不得使用新配置执行。
- `selected_model.id` 与顶层原始模型 ID 一致，且规范化选中模型记录与 `selected_model_digest` 相符；目录版本和目录摘要作为上游目录的审计信息保留。
- 适配器具有当前模式的执行路径。

模型目录刷新不会改变已经创建任务中的选中模型记录，也不要求目录版本仍等于连接的最新目录版本。如果模型随后从上游下线，任务使用原始模型 ID 提交，并按上游的模型不可用错误失败；不得静默选择替代模型。

任务创建后，地址、密钥或适配器等执行配置发生变化时，旧任务不能被静默路由到新地址、新密钥、新适配器或其他模型。需要用户基于最新连接重新提交。

外部任务的唯一执行目标是快照中的外部连接。任何鉴权、网络、协议、模型、限流、适配器或上游错误都直接使外部任务失败或进入可重试状态；不得调用 Lovart，不得改用 Lovart 模型，也不得把外部任务重新标记成 Lovart 任务。

## 错误与恢复

服务端继续使用稳定错误码，工作台把错误转换为中文、可操作的消息：

| 场景 | 用户消息与操作 |
| --- | --- |
| 地址格式错误 | “API 地址格式不正确，请填写完整地址，例如 `https://api.example.com/v1`。”并聚焦地址输入框 |
| `401` 或 `403` | “API Key 无效或没有读取模型的权限。”提供“更新密钥” |
| 地址不可达 | “无法连接到该 API，请检查域名、网络或地址路径。”提供“修改地址” |
| 未识别协议 | “该 API 暂不支持自动识别。”不提供 JSON 入口 |
| 模型响应为空 | 保存为未启用或无模型状态，提供“重新识别” |
| 上游限流 | 显示可用的等待时间并提供稍后重试 |
| 上游服务错误 | 显示脱敏摘要和连接名称，不显示密钥或完整响应 |
| 自动刷新失败 | 使用上一次成功目录，标注“模型列表可能已过期” |
| 模型已下线 | 刷新目录并要求用户重新选择，不静默替换模型 |
| 没有当前模式适配器 | 模型可在连接详情查看，但生成入口禁用并显示“当前版本暂不支持调用” |

错误信息不能直接把内部字段名如 `base_url`、`endpoint_mappings` 或解析路径暴露给普通用户。

## 安全与隐私

- API Key 只写入 IMVIA 本机安全凭据助手。
- 密钥不得进入浏览器状态、连接 JSON、模型目录、任务快照、Codex 消息、日志或错误响应。
- 连接和模型公共响应必须递归移除疑似密钥、令牌、授权头和服务商原始敏感字段。
- 只允许 HTTPS；禁止 URL 用户名、密码、查询参数和片段。
- 默认阻止回环、本机、局域网、链路本地和云元数据地址。
- DNS 解析、每次重定向和最终连接目标都必须执行同等网络安全校验，避免 DNS 重绑定和重定向绕过。
- 自动探测只能执行受信任适配器定义的只读模型请求。
- 限制候选路径数量、请求时间、响应体大小、模型数量、模型字段长度和重定向次数。
- 日志只记录连接公共 ID、适配器 ID、阶段、脱敏错误码和耗时。
- 删除连接只能删除 IMVIA 自己管理的凭据引用，不影响独立 Lovart 插件或其他凭据。

## 旧版连接兼容

已有 `custom-rest` 连接按原配置继续运行，保持原 `connection_id`、配置版本、凭据引用、接口映射和设置。它们在连接列表中标记为“旧版连接”。

旧版连接遵守以下规则：

- 不自动转换为新适配器连接。
- 不在新版简化编辑器中暴露或重写原始 JSON。
- 继续提供测试、停用、删除和更新密钥。
- 修改地址或转换到自动识别流程时，创建新的自动识别连接；成功后由用户明确停用旧连接。
- 已有任务继续引用原连接和配置版本。

新建连接不再创建 `custom-rest` 用户映射。旧版能力只作为迁移兼容层保留。

## 测试策略

### 单元测试

- 地址规范化、HTTPS 要求和主机安全规则。
- 协议识别候选顺序、同主机限制和未知结构拒绝。

## 验收标准

1. 新连接界面不显示或要求任何 JSON。
2. 用户只提供 API 地址和 API Key 即可完成连接；API 名称可选且推荐填写。
3. 名称为空时自动使用域名，并可靠处理重名。
4. 受支持 API 的模型名称和 ID 按上游返回原样展示。
5. 所有安全模型都可在连接详情查看；生成选择器只启用存在可靠执行路径的模型。
6. OpenAI-compatible 标准图片模型可以通过对应适配器生成。
7. 视频模型只有在匹配到受支持视频适配器时启用，不通过名称猜测协议。
8. 识别、刷新和生成错误都有中文、可操作且脱敏的提示。
9. 模型刷新失败不会清空上一次成功目录或破坏既有任务快照。
10. API Key 不出现在浏览器、持久化连接、模型目录、任务快照、Codex 消息、日志或错误文本中。
11. 外部 API 失败时不会发起任何 Lovart 请求。
12. 已有旧版自定义 REST 连接保持可读取、可执行且不丢失配置。
13. 相关测试、插件验证、重新安装和安装缓存核对全部完成。
